## 四、数据库配置

### 4.1 配置文件

**文件路径**：`dbconfig/database.py`

### 4.2 配置项

| 配置项  | 环境变量          | 默认值         | 说明       |
| ---- | ------------- | ----------- | -------- |
| 主机   | `DB_HOST`     | `127.0.0.1` | 数据库服务器地址 |
| 端口   | `DB_PORT`     | `3306`      | 数据库端口    |
| 用户名  | `DB_USER`     | `menu`      | 数据库用户名   |
| 密码   | `DB_PASSWORD` | `menu.123`  | 数据库密码    |
| 数据库名 | `DB_NAME`     | `menu`      | 数据库名称    |
| 字符集  | `DB_CHARSET`  | `utf8mb4`   | 数据库字符编码  |

### 4.3 核心函数

| 函数名                       | 文件路径                   | 功能说明             |
| ------------------------- | ---------------------- | ---------------- |
| `get_db_connection()`     | `dbconfig/database.py` | 获取MySQL数据库连接     |
| `get_all_tags_cache()`    | `dbconfig/database.py` | 获取所有标签（从数据库）     |
| `get_dish_tags_mapping()` | `dbconfig/database.py` | 获取菜品-标签映射关系      |
| `get_tag_caches()`        | `dbconfig/database.py` | 获取标签缓存（带30秒自动刷新） |
| `clear_tag_cache()`       | `dbconfig/database.py` | 清除标签缓存           |
| `clear_dish_tags_cache()` | `dbconfig/database.py` | 清除菜品标签映射缓存       |

### 4.4 缓存机制

- **缓存有效期**：30秒（`CACHE_EXPIRE_SECONDS`）
- **自动刷新**：每次调用 `get_tag_caches()` 时检查是否过期
- **手动刷新**：调用 `clear_tag_cache()` 或 `POST /api/cache/refresh`

### 4.5 数据库表结构（参考）

```sql
-- 标签表
CREATE TABLE tags (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    background_color VARCHAR(20),
    text_color VARCHAR(20)
);

-- 菜品表
CREATE TABLE dishes (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10,2),
    image VARCHAR(255),
    description TEXT,
    detail_desc TEXT,
    ingredients TEXT,
    method TEXT
);

-- 菜品标签关联表
CREATE TABLE taglink (
    dish_id INT,
    tag_id INT
);

-- 订单表
CREATE TABLE mu_order (
    id INT PRIMARY KEY AUTO_INCREMENT,
    order_number VARCHAR(50),
    user_id INT,
    total_amount DECIMAL(10,2),
    status INT DEFAULT 0,
    created_at DATETIME
);

-- 订单菜品关联表
CREATE TABLE mu_orderlink (
    order_id INT,
    dish_id INT,
    quantity INT,
    price DECIMAL(10,2)
);

-- 用户表
CREATE TABLE users (
    id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) UNIQUE NOT NULL,
    password VARCHAR(64),  -- MD5加密
    balance DECIMAL(10,2) DEFAULT 0,
    is_admin TINYINT DEFAULT 0
);

-- 每日推荐表
CREATE TABLE daily_recommend (
    date DATE PRIMARY KEY,
    dish_id INT
);
```

## 八、安全说明

### 8.1 权限控制

| 权限类型  | 验证方式                   | 涉及接口                          |
| ----- | ---------------------- | ----------------------------- |
| 登录验证  | Session检查              | `/api/user/*`, `/api/order/*` |
| 管理员验证 | Session + `is_admin`字段 | `/api/ops/*`, 每日推荐管理          |
| 密码加密  | MD5哈希                  | 所有用户密码存储                      |

### 8.2 运维接口限制

- **数据库测试**：执行真实连接测试，可能暴露数据库结构
- **密码重置**：可重置任意用户密码，需管理员权限
- **接口测试**：仅允许访问本地地址（127.0.0.1/localhost），防止SSRF攻击

### 8.3 配置管理

- **密钥存储**：`app.secret_key` 硬编码在 `app.py` 中（生产环境建议改为环境变量）
- **数据库密码**：默认值在 `dbconfig/database.py` 中（生产环境必须通过环境变量覆盖）

## 九、常见问题排查

### Q1: 数据库连接失败

**排查步骤**：

1. 检查数据库服务是否运行
2. 确认网络连通性：`ping 数据库主机`
3. 验证端口是否开放：`telnet 主机 端口`
4. 测试运维接口：`POST /api/ops/db-test`
5. 查看日志文件中的错误信息

### Q2: 标签/菜品缓存不更新

**排查步骤**：

1. 等待30秒缓存过期
2. 手动调用 `POST /api/cache/refresh`
3. 或重启应用服务

### Q3: 用户登录失败

**排查步骤**：

1. 检查用户名密码是否正确
2. 确认Session是否正常（检查Cookie设置）
3. 查看数据库中用户密码是否正确（MD5加密）
4. 检查 `app.secret_key` 是否变更（会导致已有Session失效）

### Q4: 运维接口无法访问

**排查步骤**：

1. 确认已登录管理员账号
2. 检查Session中 `is_admin` 字段是否为True
3. 查看 `routes/ops.py` 中 `require_admin()` 函数逻辑

### Q5: 前端样式错乱

**排查步骤**：

1. 检查浏览器控制台是否有CSS加载错误
2. 确认 `style.css` 中的 `@import` 路径正确
3. 强制刷新：`Ctrl + Shift + R`
4. 检查各CSS文件是否完整
